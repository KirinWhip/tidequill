# 手动测试清单 / Manual tests (v1.0.1)

自动测试（单元测试 + Playwright E2E，Linux 和 Windows CI）使用本地 mock 服务器，覆盖不到真实账号、真实硬件和系统集成。下面每一项都写明前置条件、步骤和预期结果。环境：Windows 10/11 x64。完成后在每项后面记录 通过 / 失败 + 日期 + 备注。

数据目录：`%APPDATA%\Tidequill`（在资源管理器地址栏输入即可打开）。

---

## 1. 自动更新：已安装的 1.0.0 → 1.0.1

前置条件：
- 本机已用 **安装版** `Tidequill-Setup-1.0.0-x64.exe` 安装 1.0.0（便携版不支持自动更新，见第 1.6 步）。
- GitHub 上 v1.0.1 已发布并标记为 Latest，Release 中有 `latest.yml`、`Tidequill-Setup-1.0.1-x64.exe` 和对应的 `.blockmap`。
- 网络可以访问 github.com（如需代理，先在 1.0.0 的 设置 → 网络 中填好；注意：1.0.0 的更新下载走系统代理，见下方“已知情况”）。

步骤：
1. **备份数据**：完全退出 Tidequill（托盘图标 → 退出），把 `%APPDATA%\Tidequill` 整个复制一份到别处。
2. 启动 1.0.0。打开 关于，确认显示“当前版本：1.0.0”。记下现有对话数量、一个对话的标题和最后一条消息。
3. 触发检查（两种方式任选其一）：
   - a. 设置 → 系统 已勾选“启动时检查更新”（默认勾选）：重启应用，几秒后侧边栏顶部出现“发现新版本：1.0.1”和“下载并安装”按钮。
   - b. 设置 → 系统 → “检查更新”：按钮旁显示“发现新版本：1.0.1”（这里只提示，不下载）。然后重启应用，用方式 a 的按钮下载。
4. 点侧边栏的 **下载并安装**。按钮变为转圈；下载约 100 MB（取决于网速）。下载完成后应用自动退出并启动安装程序。
   - 安装包未签名，可能出现 SmartScreen 或 UAC 提示：确认发布者为“未知”，选择“仍要运行 / 是”。
   - 安装程序会沿用原来的安装目录；完成后自动启动 Tidequill。
5. 验证：
   - 关于 显示“当前版本：1.0.1”，运行环境行显示 `Electron 44.7.2`。
   - 第 2 步记下的对话、标题和消息都在；设置（提供方、密钥）都在，发送一条消息正常。
   - 若装有插件：启动后弹出“加载新插件？”窗口，显示插件路径和 SHA-256（预期行为，见 CHANGELOG 升级说明）。
   - 若有已启用的 stdio MCP 服务器：插件/工具 页该服务器显示“命令未确认，未启动”，点“查看并确认”后显示完整命令行，确认后变为 connected。
   - `%APPDATA%\Tidequill\backups` 目录已生成，`trust.json` 已生成，旧的 `tool-allowlist.json` 已删除。
   - 控制面板 → 程序和功能 中 Tidequill 版本为 1.0.1，只有一项（没有重复安装）。
6. 便携版：运行 `Tidequill-1.0.0-portable.exe`，设置 → 系统 → 检查更新。预期：提示“当前安装方式不支持自动更新”一类信息，或发现新版本但需要手动下载新的便携版；便携版不会自动替换自身。（记录实际提示文字。）

失败时收集：`%APPDATA%\Tidequill\logs`（若存在）、`%LOCALAPPDATA%\tidequill-updater\` 下的文件列表和 `installer.exe` 是否存在、屏幕截图。

已知情况：
- 更新程序校验的是 `latest.yml` 中的 sha512，不校验代码签名（安装包本身没有签名）。
- 1.0.0 的更新下载由 electron-updater 发起，**不使用** 应用里的“代理”设置，而是系统代理。只能通过代理访问 GitHub 时，请先设置系统代理；否则手动下载 1.0.1 安装版覆盖安装（数据同样保留）。

## 2. 开机自动启动（Windows）

1. 设置 → 系统，勾选“开机自动启动”（同时建议勾选“最小化到系统托盘”）。
2. 打开 任务管理器 → 启动应用：应出现 Tidequill，状态“已启用”。（也可以在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中看到 Tidequill 项。）
3. 注销或重启 Windows 并登录：Tidequill 自动启动（窗口打开，或在托盘中）。
4. 回到 设置 → 系统，取消勾选。任务管理器 → 启动应用 中 Tidequill 消失或显示“已禁用”；再次重启后不自动启动。
5. 便携版重复第 1–3 步：记录行为（便携版启动项指向当前 exe 路径，移动 exe 后会失效，这是预期）。

## 3. 旧数据迁移（ChatBox Clone → Tidequill）

适用于 0.x（产品名 ChatBox Clone）用户。应用只在 `%APPDATA%\Tidequill\data` **不存在** 时，从 `%APPDATA%\ChatBox Clone` 复制一次 `data`、`plugins` 和 `tool-allowlist.json`；旧目录保留不删。

1. 退出 Tidequill。把现有的 `%APPDATA%\Tidequill` 改名为 `Tidequill.bak`（测试完再改回）。
2. 准备旧数据：
   - 如果本机有 0.x 的真实数据，确认 `%APPDATA%\ChatBox Clone\data\conversations.json` 存在；
   - 否则手动创建 `%APPDATA%\ChatBox Clone\data\conversations.json`，内容：
     `[{"id":"legacy1","title":"旧版对话","pinned":false,"providerId":"x","model":"m","systemPrompt":"","createdAt":1700000000000,"updatedAt":1700000000000,"messages":[{"id":"u1","role":"user","content":"来自旧版的消息","createdAt":1700000000000}]}]`
3. 启动 Tidequill 1.0.1。
4. 预期：侧边栏出现旧对话（真实数据则全部出现），内容一致；`%APPDATA%\Tidequill\data` 被创建；`%APPDATA%\ChatBox Clone` 仍然存在、内容未变。
5. 旧数据中如有插件：启动时弹出插件确认窗口（1.0.1 新行为）。旧的 `tool-allowlist.json` 会被复制过来，随后被 1.0.1 删除（旧授权不区分来源，需要重新授权）。
6. 再次重启：不会重复复制（修改一个对话标题后重启，标题保持修改后的值）。
7. 恢复：退出，删除测试生成的 `%APPDATA%\Tidequill`，把 `Tidequill.bak` 改回原名。

## 4. 真实 DeepSeek 深度思考

前置：DeepSeek 官方 API 密钥（platform.deepseek.com），有少量余额。

1. 设置 → 模型提供方 → DeepSeek，填写密钥，点“测试连接”：显示成功和模型数量。
2. 新建对话，选择 `deepseek-v4-pro`（或 `deepseek-flash`），打开输入框上方的“深度思考”（或 `Ctrl+D`）。
3. 发送：“9.11 和 9.9 哪个大？请一步步想。”
4. 预期：回复上方出现可折叠的“思考过程”，流式显示思考内容，然后显示正文；结束后思考过程默认折叠，可展开。
5. 对话设置（齿轮）→“查看本次请求内容”：请求体中有 `"thinking": {"type": "enabled"}` 和 `"reasoning_effort": "high"`，地址中的密钥已脱敏。
6. 关闭“深度思考”再发送一次：不出现思考过程；请求体中有 `"thinking": {"type": "disabled"}`。
7. 打开“工具”并启用内置工具（设置 → 对话 → 发送内置演示工具），开启深度思考，发送“现在几点？”：工具调用确认框出现，允许后模型给出时间，不报 400 错误（验证带工具时回传 `reasoning_content`）。

## 5. 真实 token 数

1. 设置 → 用量与费用，勾选“显示 Token 用量与估算费用”。
2. 用任一真实提供方（DeepSeek / OpenAI / Claude / Gemini 各测一次更好）发送“你好”。
3. 预期：消息底部显示输入 / 输出 token 数，数值来自提供方返回的 usage（不是估算）。
4. 与提供方控制台对比：在 DeepSeek / OpenAI 的用量页面找到同一时间的请求，输入和输出 token 数一致（控制台通常有几分钟延迟）。
5. 输入框上方的上下文估算值与实际输入 token 数在同一数量级（估算值，允许偏差）。
6. 模型没有配置价格时显示“未配置价格”，点击后跳到价格表并可一键添加。

## 6. Windows 标题栏按钮

1. 浅色主题：标题栏右侧的 最小化 / 最大化 / 关闭 按钮背景与标题栏一致（浅灰），图标为深色；没有出现系统强调色。
2. 设置 → 通用 → 主题 切换为深色：按钮背景和图标颜色立即随之变化。切换“跟随系统”并在 Windows 设置中切换深浅色：同样跟随。
3. 依次点击：最小化（窗口到任务栏）、最大化 / 还原（图标切换）、关闭（开启托盘时隐藏到托盘，未开启时退出）。
4. 拖动标题栏空白处可以移动窗口；双击标题栏空白处最大化 / 还原。
5. 将鼠标移到最大化按钮上：Windows 11 显示贴靠布局浮层。
6. 在 125% / 150% 缩放的显示器上重复 1–4：按钮与标题栏高度对齐，标题文字不被按钮遮挡。

## 7. 真实麦克风（语音输入）

前置：一个 OpenAI 兼容的转写接口（OpenAI 密钥 + `whisper-1` 或 `gpt-4o-mini-transcribe`）；Windows 设置 → 隐私和安全性 → 麦克风 中允许桌面应用访问麦克风。

1. 设置 → 对话 → 语音输入，勾选“在输入框显示麦克风按钮”，选择提供方和模型，语言填 `zh`。
2. 点输入框下方的麦克风按钮：任务栏 / 系统托盘出现“正在使用麦克风”图标，按钮变为录音状态。
3. 说“今天天气怎么样”，再点一次按钮停止：显示转写中，随后文字插入输入框（不自动发送）。
4. 不点按钮时，系统托盘不应出现麦克风使用图标（应用不会在后台录音）。
5. 在 Windows 隐私设置中关闭桌面应用的麦克风权限，再点按钮：显示“麦克风不可用：…”的提示，应用不崩溃。
6. 设置一个错误的密钥：停止录音后显示“转写失败：…”及原因。

## 8. 中文 OCR

1. 设置 → 对话 → 图片文字识别（OCR），勾选“简体中文”（chi_sim），点“下载”：显示“已下载 约 1.7 MB”。（网络不通时可把下载地址改为可访问的镜像，`{lang}` 会被替换为语言代码。）
2. 勾选“添加图片时识别其中的文字”。
3. 准备一张清晰的中文截图（例如本 README 的一段文字截图），拖入输入框。
4. 预期：显示“正在识别图片文字…”，随后多出一个“<文件名>（识别文字）”附件；打开附件，主要文字识别正确（允许个别字错误）。
5. 断网后再添加一张图片：仍能识别（识别在本机进行，语言数据已下载）。
6. 取消勾选 OCR 后添加图片：不再生成识别文字附件。

## 9. 真实联网搜索

前置：任选一个真实服务：Tavily 密钥（tavily.com 免费额度）、Brave Search 密钥，或自建 SearXNG（`settings.yml` 中 `search.formats` 包含 `json`）。

1. 设置 → 联网搜索：选择服务，填写密钥（SearXNG 填地址），点“测试搜索”：显示“搜索成功，返回 N 条结果”。
2. 退出并重新打开应用，检查 `%APPDATA%\Tidequill\data\settings.json`：搜索密钥不是明文（为加密后的字符串）。
3. 新建对话，打开输入框下方的“联网搜索”开关，发送“今天的主要科技新闻有哪些？”。
4. 预期：先显示正在搜索，然后回复中出现 [1]、[2] 等可点击编号，回复下方列出“来源”卡片；点击编号或卡片在系统浏览器中打开对应网页，内容与回复相关。
5. 对话设置 →“查看本次请求内容”：搜索结果附加在本次用户消息中；对话正文中的用户消息仍然只是原问题。
6. 把密钥改错再发送：回复上方说明搜索失败的原因，回复照常生成。

## 10. 真实显示器 DPI 与窗口布局（1.0.2，A2）
CI 只能在虚拟显示器上用 `--force-device-scale-factor` 模拟缩放，无法覆盖真实显示器、贴靠和多显示器。请在真实 Windows 10/11 上逐项检查：

| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| 10.1 | 100% 缩放 | 设置 → 显示 → 缩放 100%，启动后双击标题栏最大化 | 窗口四边与工作区对齐，任务栏不被遮挡，右上角三个按钮完整可见 |
| 10.2 | 125% 缩放 | 同上，缩放 125%（注销或重启应用） | 同上；文字清晰无模糊 |
| 10.3 | 150% 缩放 | 同上，缩放 150%，屏幕 1366×768 或 1920×1080 | 同上；还原后窗口不超出屏幕（最小尺寸会按工作区收紧） |
| 10.4 | 贴靠 | Win+← / Win+→、拖到屏幕边缘、Win+Z 贴靠布局 | 窗口占半屏/布局区域，无超出、无黑边 |
| 10.5 | 多显示器 | 两台不同缩放的显示器（如 100% + 150%），把窗口拖到另一台后最大化 / 还原 | 每台上都贴合该屏工作区；跨屏拖动时尺寸合理 |
| 10.6 | 任务栏位置 | 任务栏放在左 / 上 / 自动隐藏 | 最大化后不覆盖任务栏 |

记录：Windows 版本、显示器分辨率与缩放、截图。若最大化后仍超出，请附 设置 → 系统 → 诊断信息。
